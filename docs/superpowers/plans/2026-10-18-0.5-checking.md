# 0.5 Checking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Per-container watch rules (labels or UI), skip/snooze for updates, release-notes links, dashboard filters and search, a random start delay and check-on-startup setting, a heartbeat ping, and a read-only layout check that flags anything a container keeps outside `COMPOSE_ROOT` – shown on the dashboard, a Layout page, the digest and the "Layout problems" notification.

**Architecture:** Inventory gains each container's `docker-manager.*` labels, its mounts and the image's source label. A `rules` module merges labels with UI-saved overrides (label wins) and feeds the checker (watch on/off, tag include/exclude) and the notifier (notify on/off). Skips live in a new table and are applied when building views, digests and notifications – the stored check result stays the raw truth. The layout check is a pure function of the inventory and settings, stored alongside the check result.

**Tech Stack:** Python 3.12, FastAPI, Jinja2, SQLite, APScheduler, `regex` (new dependency – Python's `re` has no timeout; `regex` supports `timeout=`), vanilla JS.

**Spec:** `docs/superpowers/specs/2026-10-18-settings-auth-notifications-design.md` – section 4, release item 4. 0.2–0.4 code is on `main`.

## Global Constraints

- UK English; en dash (–), never em dash.
- Labels (exact names): `docker-manager.enable` (`false` → not watched), `docker-manager.include_tags`, `docker-manager.exclude_tags` (each `;`-separated regexes, matched against the **whole** tag), `docker-manager.notify` (`false` → left out of the digest and "Updates found"), `docker-manager.release_notes` (URL, `https://` or `http://` only), `docker-manager.layout.ignore` (`true`). A label always wins over the UI value for the same rule; values are case-insensitive for booleans (`true/false/yes/no/1/0`); an invalid value is ignored and shown as a warning on that container.
- Regexes: compiled with the `regex` package; each match uses `timeout=0.05` s; a timeout or compile error makes that pattern count as "no match" and is reported as a warning (never hangs or crashes a check). Max 10 patterns per rule, 200 characters each.
- Container identity for rules and skips: `"<project>/<service>"` for compose containers, else the container name.
- Skip/snooze: Operator+; "Skip this version" hides that exact update (build: remote digest; minor/major: tag; Mailcow: release) until a different one appears; "Snooze" hides any update of that kind for that container for 7 or 30 days. Optional reason (≤ 200 chars). Reversible. Every skip, snooze and removal audited (kind `updates`) with who and reason. Skipped/snoozed items are excluded from the "needs update" counts, attention cards, digest "available" sections and "Updates found" – and listed under the dashboard "Skipped" filter and a digest "Skipped" line count.
- Release-notes link, in order: the `release_notes` rule; else image label `org.opencontainers.image.source` if it is `https://github.com/<owner>/<repo>` (→ `…/releases`); else for Docker Hub images `https://hub.docker.com/r/<namespace>/<repo>/tags` (`_/<repo>` for library images). Links open in a new tab with `rel="noopener noreferrer"`.
- Settings (Checking section, editable in the UI; new ones UI-only, no env): `check_on_startup` (bool, default on), `random_delay_minutes` (int 0–60, default 0), `heartbeat_url` (optional; `https://` or `http://`; no credentials in the URL), `layout_check` (bool, default on), `named_volumes_allowed` (bool, default off), `layout_allowlist` (list of absolute paths, one per line, ≤ 50).
- Heartbeat: after every **scheduled** check, `GET <url>` on success or `GET <url>/fail` on a failed check (the 0.4 `check_failed` rule); 10 s timeout; no retries; failures logged with the exception type only; never delays or fails the check.
- Layout check rules exactly as the spec's table; allowed without a flag: `/var/run/docker.sock`, `/run/docker.sock`, `/etc/localtime`, `/etc/timezone`, `/dev` and anything under it, `/proc`, `/sys` (when mounted read-only), anonymous volumes, tmpfs, the Mailcow folder and Mailcow's own containers, the dashboard's own `DATA_DIR` mount, anything under a `layout_allowlist` entry, and containers with `layout.ignore`. It never changes anything.
- Stored check results from 0.4 must still load (new fields default when absent).
- Roles: dashboard, Layout page and release-notes links – Viewer; skip/snooze and per-container watch rules – Operator; Checking settings – Admin.

## Review Focus

1. **A pathological regex** (e.g. `(a+)+$` against a long tag) in a label – the check finishes on time, the pattern is reported, other containers are unaffected.
2. **A skipped version then a newer one** – the newer one shows and notifies; a snooze expires on time; removing a skip brings the update back immediately.
3. **Upgrading from 0.4** – the stored check result loads, no new notification floods (layout problems already present on first check after upgrade are baselined like updates, see Task 6), Checking settings keep their values.
4. **Layout false positives** on a typical server – the dashboard's own `/data`, `docker.sock`, `/etc/localtime`, Mailcow, tmpfs and anonymous volumes are not flagged.
5. **Label vs UI** – a label always wins and the UI shows the field as "Set by a label on the container".

### Task 2: Watch rules (labels + UI) and how the checker uses them

**Files:** Create `app/rules.py`, `app/templates/container_rules.html`, `tests/test_rules.py`, `tests/test_rules_routes.py`. Modify `pyproject.toml` (`regex==<newest major>.*`), `app/checker.py`, `app/versions.py` (optional tag filter), `app/main.py` (routes), `tests/test_roles_routes.py`.

**Interfaces – Produces:**
- `@dataclass(frozen=True) class Rules: watch: bool = True; include_tags: tuple[str, ...] = (); exclude_tags: tuple[str, ...] = (); notify: bool = True; release_notes: str | None = None; layout_ignore: bool = False; from_label: frozenset[str] = frozenset(); warnings: tuple[str, ...] = ()`
- `class RulesStore(store)`: `saved(key) -> dict`, `save(key, form: Mapping[str,str], user) -> None` (validates like labels; raises `RulesError(.errors)`; audits kind `updates` "Watch rules changed: <key>"), `effective(info: ContainerInfo) -> Rules` (label wins per field; invalid label values → warning and fall back to the UI value or default). Stored as one settings row `container_rules` (plain JSON, no secrets).
- `def tag_allowed(tag: str, rules: Rules) -> bool` – include (if any) must match, exclude must not; uses `regex.fullmatch(p, tag, timeout=0.05)`; timeouts/errors → that pattern counts as no match and a warning is added (the warning is collected per check run, not raised).
- Checker: `check_all(..., rules_for: Callable[[ContainerInfo], Rules] | None = None)`. `watch=False` → new `Status.NOT_WATCHED` ("Not watched"), no registry calls for that image (unless another watched container uses it); version candidates filtered by `tag_allowed` before `find_version_updates` (pass the filtered tag list); `ContainerStatus` gains `rule_warnings: list[str]` and `notify: bool`.
- Routes (Operator): `GET /containers/{key:path}/rules` form (each field shows "Set by a label on the container" and is disabled when `from_label`), `POST /containers/{key:path}/rules` (CSRF). A "Watch settings" link on each dashboard row. Unknown key → 404.

### Task 6: Layout check

**Files:** Create `app/layout.py`, `app/templates/layout.html`, `tests/test_layout.py`; modify `app/checker.py`/`app/main.py` (`run_check` computes layout and stores it with the result: `CheckResult.layout: list[LayoutProblem]`, default `[]`), `app/templates/dashboard.html` (project badge), `app/templates/base.html` (nav "Layout"), `tests/test_roles_routes.py`.

**Interfaces – Produces:**
- `@dataclass(frozen=True) class LayoutProblem: key: str; container: str; project: str | None; kind: Literal["bind_outside","named_volume","compose_outside","env_outside","not_compose"]; detail: str; hint: str; severity: Literal["problem","notice"]` – `key` = `"<container_key>:<kind>:<path or volume>"` (stable, for notification dedupe).
- `def layout_problems(containers: list[ContainerInfo], settings: Settings, rules_for: Callable[[ContainerInfo], Rules], data_dir: str, mailcow_dir: str) -> list[LayoutProblem]` – pure; path checks with `os.path.normpath` and "is under" by path components (so `/dockerx` is not under `/docker`); hints in plain words, e.g. bind: "Move the data to `/docker/<project>/<last part>` and change `<source>:<dest>` to `./<last part>:<dest>`"; named volume: "Move the data to `/docker/<project>/data` and change `<name>:<dest>` to `./data:<dest>`".
- `GET /layout` (Viewer) – problems grouped by project with severity, detail and hint; "Nothing stored outside /docker" when empty; disabled message when `layout_check` is off.
- Dashboard project rows: badge "<n> mount(s) outside /docker" linking to `/layout#<project>`; `data-layout` attribute for the filter (Task 4).
